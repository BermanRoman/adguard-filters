# adguard-filters

Личные фильтры AdGuard. Собраны эмпирически под macOS / Safari / AdGuard Mini.

## Подписка

| Фильтр | URL |
|---|---|
| Яндекс | `https://raw.githubusercontent.com/BermanRoman/adguard-filters/main/filters/yandex.txt` |

Подключение: **AdGuard Mini → Настройки → Фильтры → Собственные фильтры → добавить по URL**, отметить как доверенный.

Флаг «доверенный» нужен не сейчас, а на будущее: скриптлеты и JS-правила выполняются только в доверенных списках. Текущие правила работают и без него.

## filters/yandex.txt

На трёх сервисах Яндекса три разные механики доставки рекламы, поэтому и разделов в файле несколько.

| Сервис | Как приходит реклама | Чем закрыто |
|---|---|---|
| Погода | прокси-домен `static-storage.net` + слоты `Money` | сетевое правило + косметика |
| Переводчик | контейнер Директа в боковой колонке | косметика по `_R-I-` |
| Поиск | РСЯ первой стороной с `yandex.ru` | косметика по `data-dsp3p` |

### Принцип

Сетевое правило режет доставку, косметика убирает пустые контейнеры, оставшиеся на месте баннеров.

Селекторы привязаны к **смысловым подстрокам**, а не к классам целиком:

- `Money`, `money-` — внутреннее название рекламных слотов у Яндекса
- `_R-I-`, `_R-A-` — идентификаторы блоков Директа
- `advRsyaReact_` — префикс React-компонента РСЯ
- `data-dsp3p` — маркер блока от рекламной платформы

Это сделано потому, что вёрстка Яндекса обфусцирована. Хвосты CSS Modules (`AppMoneySidebar_wrap__2qJIK`) меняются при каждой сборке, а часть атрибутов (`data-4d4c86ac3b`) генерится заново при каждой загрузке страницы. Устойчиво только то, от чего зависит собственный код сайта.

## Обновление

```sh
# поправить правила в filters/yandex.txt, затем:
bin/bump                    # 1.1.0 → 1.1.1
bin/bump minor              # 1.1.3 → 1.2.0
bin/bump --dry-run          # посмотреть без записи
bin/bump --help

git add -A && git commit -m 'описание правки' && git push
```

**Версию поднимать обязательно.** AdGuard решает, применять ли обновление, по строке `! Version:`. Если её не тронуть, файл на GitHub обновится, а в браузере останутся старые правила — симптом при этом никак не проявляется. Для этого и написан `bin/bump`.

`! Expires: 12 hours` — как часто AdGuard проверяет файл. Можно не ждать и обновить фильтры вручную из интерфейса.

После обновления стоит убедиться, что счётчик правил у списка изменился.

## Диагностика

Когда где-то вылезает серый прямоугольник или возвращается баннер — значит Яндекс переименовал классы. Порядок разбора, который сработал при составлении фильтра:

1. **Список загруженных доменов** через `performance.getEntriesByType('resource')` — сразу видно посторонние прокси на фоне легитимной статики.
2. **Пустые блоки заметного размера** — показывает, что осталось после сетевых правил.
3. **Поиск по смысловым подстрокам** в `class` и `id`: `money`, `adv`, `rsya`, `banner`, `promo`.
4. **Служебные атрибуты** — `data-dsp3p` оказался надёжнее любых классов.

Заблокированные запросы не попадают в Performance API, поэтому пустой результат в п. 1 означает, что правила работают, а не что рекламы нет.

## Ограничения Safari

AdGuard Mini конвертирует правила в формат Safari Content Blocker, и часть синтаксиса теряется. **Не работают:** `$redirect`, `$redirect-rule`, `$csp`, `$cookie`, `$removeparam`, `$removeheader`, `$replace`, `$header`, HTML-фильтрация (`$$`).

Это не мелочь. Правило из штатного Русского фильтра AdGuard

```
||yandex.ru/ads/system/context.js$script,xmlhttprequest,redirect-rule=noopjs
```

в Safari не работает вообще — отсюда и понадобился этот список.

Осторожно с исключениями: `@@`-правила без модификаторов в Safari размещаются в конце и отключают заодно всю косметику на домене.
